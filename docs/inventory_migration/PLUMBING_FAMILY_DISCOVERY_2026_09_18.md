# Plumbing family discovery — ongoing, not release approval

## First family: symmetric pressure tees

The development fixture proves software behavior only. Before using a real
family, explicitly establish material, dimensional system, connection at every
opening, run/branch roles, geometry, and supported variants. A general pressure
tee must not silently include directional drainage tees, press-system products,
or manufacturer-specific fittings with different defining properties.

Run reversal is an identity equivalence only for a family whose geometry permits
it. Swapping whole run ports preserves their connection characteristics. The
branch stays distinct. Neither possible geometry nor a size-series Cartesian
product proves that a fitting is manufactured.

## New failure modes identified

1. Treating a catalog size label as an actual dimension can join different parts.
2. Inferring opening order from an unexplained three-number string can move the
   branch and change physical identity.
3. Applying one supplier's certifications or application claims to a generic
   family can create unsupported safety claims.
4. Treating a source's two package identifiers as two physical items can double
   the catalog; treating them as identical without verifying packaging can also
   corrupt purchase-unit conversion. Preserve identifiers until understood.
5. Different fetched versions of a paginated supplier page may disagree. A live
   URL alone is not a reproducible release oracle; evidence needs a reviewed,
   versioned factual record with a date and precise locator.

These points require explicit acceptance policy and tests before real catalog
records are promoted. No real product rows have been promoted by this research.
